# 词萤 1.3 产品方案：让学过的词，在生活里亮起来

日期：2026-11-06。基线：当前工作区 `1.2.1`，包含尚未提交的功能；不代表应用市场已发布状态。

这份方案来自源码、离线资源、实施记录及仓库现有截图的扫描。没有运行真机，没有用户访谈、留存或学习效果数据。下述优先级是站在使用者角度的产品判断，数量和工期是建议范围。

## 1. 我的判断

如果我是词萤用户，我最想要三件事：读文章时点词能查到合适的意思；收藏的句子以后真的会再遇见；背完单词后持续有适合自己的内容可读。

建议 1.3 的主线是：**查得准 → 读得下去 → 隔天在原句里想起来。** 延续离线、轻量、温和的特点，把现有能力做成值得持续使用的体验。

## 2. 现在已经有什么

- 学习主线：每日计划、间隔复习、会话续学、撤销判断、三分钟速学、积压缓冲。
- 专项练习：认义、听音写词、拼写、语境填空；逐词保存正确性、提示使用与作答时间；已有薄弱词定向推荐和词详情证据。
- 场景功能：睡前复盘、后台听词、跟读录音对比、星图、补光、桌面卡片、多端布局和键盘操作。
- 阅读：四篇原创离线短文、理解题、按已学词形覆盖推荐、段落续读、点词、原句收藏、备注和回到原文。
- 数据：多格式词书导入导出、完整 v4 JSON 备份、恢复预览、安全副本与失败还原。自动账号同步尚未实现。

这些能力均不能再次当作 1.3 新功能包装。依据：[三轮更新](THREE_ROUNDS_UPDATE.md)、[V2 实施记录](UPGRADE_V2_IMPLEMENTATION.md)、当前 `Index.ets` 及相关页面和服务。

## 3. 扫描发现的关键缺口

### 3.1 考试词书正在承担通用词典的工作

静态资源实测：五本词书共 26,071 个书内条目，去重后为 10,689 个词头。`blue`、`umbrella`、`find`、`be`、`went`、`cat`、`dog` 未收录。

`found` 当前只有“建立、创立、铸造”；`might` 只有“力量、权力”；`may` 只有“五月”。第一篇精选短文就出现 `found`、`blue`、`umbrella`，因此问题会出现在用户最早接触的阅读体验中。

构建脚本先按考试标签筛选，再只取第一条中文释义，且没有保留 `exchange` 词形字段。阅读查询虽有规则后缀候选，但精确命中优先，不做不规则词形处理。这解释了缺词和部分常用义项缺失；不能将问题全部归咎于上游词典。

依据：[构建脚本](../tools/build_dictionary.py:73)、[词形候选](../entry/src/main/ets/utils/ArticleTokenizer.ets:41)、[阅读查询](../entry/src/main/ets/service/ArticleService.ets:60)、[已知边界](THREE_ROUNDS_UPDATE.md:74)。

### 3.2 语境入口已经丰富，内容覆盖还浅

附有至少一组非空双语例句的词头为 1,388 / 10,689，约 13.0%。口径为：词书自带 298 个词头，原创包覆盖 1,194 个词头，交集 104 个。原创包实际不同句子为 301 条，不能称为 1,194 条不同例句。

这不是“可出题率”：有效挖空位置、词形匹配与其他已学选项等条件仍会限制实际出题。新增页面的收益受内容质量约束。

### 3.3 收藏留下了材料，尚未形成再次回忆的路径

“我的原句”目前支持浏览、查看词条和备注、返回来源。现有语境挑战使用词条例句及补充包；没有把个人收藏原句作为练习来源，也没有原句搜索和来源筛选。

依据：[原句列表](../entry/src/main/ets/pages/SentenceCollectionPage.ets:36)、[语境练习取题](../entry/src/main/ets/pages/ClozeChallengePage.ets:75)、[原句模型](../entry/src/main/ets/model/ExperienceModels.ets:11)。

## 4. 三项主更新

### P0：离线查词升级——常见词查得到，词形和义项看得明白

**用户感受：** “我点 found，能看到 find 的过去式‘找到’，也能切换到 found 本身的‘建立’。”

建议范围：

1. 建立独立的离线查询词典，优先补齐内置短文全部常见词和基础高频词；考试词书继续负责学习范围。
2. 保留常用义项与词性，避免构建时只留下首条释义；默认展示精简释义，允许展开。
3. 增加常见不规则词形映射，如 `went → go`、`children → child`。对 `found → find / found` 等歧义展示候选和说明，由用户切换。
4. 阅读、搜索、系统分享导入等入口共用查询结果，减少同一个词在不同地方表现不一致。
5. 对仍未收录的词提供“保存待补充词与原句”，允许手动填释义；先作为待整理记录，补全后再绑定学习词条。

实施要点：优先评估现有固定版本 ECDICT 数据的完整释义、词频与 `exchange` 字段。上游公开格式已经提供这些字段，具备离线提取路径；仍需对筛选结果做内容审阅。参见 [ECDICT 官方仓库](https://github.com/skywind3000/ECDICT)。不要直接把全量大词典加入每日学习。

验收：

- 对四篇现有短文和新增短文建立逐词清单，常见英文词均有可用释义或明确的歧义候选。
- `found/find`、`may`、`might`、`went/go`、`children/child` 等固定案例通过人工语境核对。
- 旧单词 ID、用户自定义释义、收藏与历史进度正确保留；升级与备份恢复可往返。
- 查询词典新增词不自动改变学习任务、学习总数或既有掌握状态。
- 不把“展示候选”宣传为准确的自动语义消歧。

### P1：我的原句回忆——让昨天收藏的句子，今天还能想起来

**用户感受：** “昨天阅读时收藏了一句话，今天能用那句话再回忆一次，不用重新去找。”

建议范围：

1. 在“我的原句”增加搜索、按来源筛选和“用这些原句回忆”。
2. 收藏时保存目标词的实际词形和在原句中的准确位置，避免一句多次出现同词时挖错位置。
3. 从符合条件的收藏里推荐最多 3–5 句；优先隔天再次出现，用户可跳过、暂停推荐或手动挑选。
4. 默认遮住当时选中的单词，要求输入原句词形；主动请求时提供词义或字母提示。输入原形时可提示“这里需要过去式”等信息。
5. 答题后展示完整原句、原词和来源，支持回原文；分别记录独立答对、提示后答对和错误。

实施要点：复用现有练习保存和计时机制，增加原句来源与跨日记录；旧收藏不能可靠定位时先让用户确认目标，不能猜测后直接出题。个人原句可能包含专名、复杂语法或错误，练习前允许预览、排除；这项功能只检查指定词形，不承担整句语法评分。

验收：同句重复出现的单词、变形词、来源文章删除、旧收藏迁移、提示与重试、备份恢复均有明确行为。练习结果不隐式改变间隔调度，也不计入每日背词配额。

### P1：分层短文——背完以后，持续有东西读

**用户感受：** “学了一周以后，推荐的文章仍然有新内容，而且我知道为什么适合我。”

建议首发将精选短文从 4 篇扩充到 **18 篇总量**，按入门、基础、进阶三个内部层次组织，覆盖生活、校园和工作等主题；这个数量是范围建议，不是已有产能。

每篇提供预计时间、主题、少量重点词、两道理解题及答案依据。复用现有续读、点词和阅读完成能力。没有经过标定前不标注 CEFR 能力等级。

推荐延续“未读、可继续、已学词形覆盖”的基础，同时减少相同主题连续出现，给出具体理由，例如“出现了你最近学过的 6 个词”。新增查询词典后，继续把“能查到”“有学习记录”“理解文章”分开表达，不能把词典覆盖当成已学覆盖或理解率。

内容补充围绕文章重点词同步提供常用义项、可核对的双语例句与搭配。先覆盖用户实际会遇到的词，逐步扩大到核心词，避免以全词库覆盖率作为首版唯一目标。

验收：18 篇的词典覆盖、题目答案、挖空位置和双语内容均审阅；读完后能看到后续未读文章；首页不反复推荐已完成内容；阅读进度与旧数据正确迁移。

## 5. 两个候选小更新

### P2：听词按自己的节奏来

已有后台听词和耳机控制，本次只加控制权：选“今日新学 / 最近薄弱 / 收藏”，回忆停顿 2 / 4 / 6 秒，10 / 20 分钟后停止。先做这三项；例句开关、单词循环可后续加入。是否听过不能直接变成“已掌握”。

### P2：一份能解释进步的每周回顾

复用现有逐词证据，展示“最近哪些词隔天无提示仍能答对”“哪些词还需要再练”。样本、日期与提示使用必须可见；样本不足时不显示没有依据的能力分数。

现有“本周真正掌握 +N”实际来自强度达到 75 的历史记录，建议改为“本周进入掌握阶段 N 词”，另列跨日练习证据。先加聚合和准确文案，不另开一种挑战。

## 6. 建议的完整使用路径

首页开始今日学习 → 本轮完成 → 读一篇适合自己的短文 → 点词看到合适的义项与词形 → 收藏原句 → 次日可选回忆 3 句 → 周末看到具体词的变化。

首页继续以今日学习为主操作；原句回忆通过现有“可选的一小步”承接，不再增加一排相同层级的功能卡。专项练习继续供用户自由选择。

## 7. 范围与实施顺序

建议由一位熟悉现有工程的开发者推进，按 **约 4–6 周的初步范围**安排，内容审阅并行；需在数据源抽样和旧数据迁移设计后重新估算，不作为交付承诺。

1. 第 1–2 周：查询词典、完整释义、词形候选与旧 ID 保持；先解决现有文章中的可复现案例。
2. 第 2–3 周：原句准确位置迁移、搜索筛选、原句回忆和独立记录。
3. 第 3–4 周：分层内容、推荐说明和首页衔接；内容审阅从第一周开始。
4. 第 5–6 周：迁移与恢复回归、多端与大字体、真机语音和后台行为、试用修正。

若范围超出预算，先发布“查词底座 + 18 篇分层短文”，将原句回忆延至 1.3.1。P2 候选不阻塞主版本。

技术涉及 `build_dictionary.py`、查询服务、阅读页面与资源、原句模型/仓库、练习记录及备份校验。是否增加数据库和备份版本，应依据最终新增字段确定，不能只改页面而遗漏旧收藏和恢复路径。

## 8. 发布前应验证什么

- **内容可靠性：** 新旧短文逐词查义、歧义词候选、题目答案依据、例句目标词形；自动结构校验配合人工审阅。
- **历史兼容：** 现有进度、词条 ID、自定义释义、旧原句、删除来源与不同版本备份恢复。
- **实际体验：** 手机大字体、平板/2in1 键盘，离线查询时延，真机语音与长时间后台听词。
- **产品试用：** 先做 5–8 位目标用户的定向试用，观察他们能否完成“读文—查词—收藏—隔天回忆”。这是建议的验证计划，尚未执行。

建议本机记录并可导出的验证口径：阅读点词命中/未命中次数；开始与完成阅读的篇次；收藏后在另一天进入回忆的原句数；跨日无提示正确题数/作答题数。必须标清时间和样本；在得到基线前，不承诺提升留存或记忆效果的百分比。

## 9. 后续独立规划

账号自动同步、云端 AI 对话、自动口语评分、完整 FSRS 迁移、依赖权益的锁屏/实况窗，分别需要独立的数据、平台或验证工作。它们可以进入后续路线图，本次优先级低于已经能复现的查词与内容缺口。

FSRS 是可继续评估的算法方向，其官方实现包含基于复习历史的参数优化；不能把本方案的跨日练习记录直接等同于完成 FSRS 适配。参见 [FSRS 官方项目](https://github.com/open-spaced-repetition/fsrs4anki)。
